Security & Privacy

When your internet connection is lost, your positions remain completely secure. Sentralyx operates with GTC Orders (Good Till Canceled) and Server-Side Protection principles:

✅ SL/TP Protection: Stop Loss and Take Profit orders are stored directly on the exchange server and remain active whether or not you have an internet connection.
  • SL (Stop Loss): When price reaches your stop level, the position automatically closes.
  • TP (Take Profit): When target price is reached, your profit is realized.
  • Global Stop: In emergency situations, you can safely close all positions.

Important: During internet outages, new orders cannot be sent (security measure), but existing positions are protected on the server side.

Your API keys are protected with maximum security using HWID encryption:

🔐 Dual-Layer Encryption: Hardware ID (HWID) and Fernet symmetric encryption combination.
  • HWID Binding: Each license is specific to a particular hardware. It won't work on different machines.
  • Local Storage: API keys are never sent to cloud or third-party servers.
  • Fernet Encryption: AES-128 based, URL-safe encryption standard is used.
  • Regulatory Compliance: Fully compliant with GDPR and KVKK data protection laws.

Additional Security: Your API keys can only be decrypted with your machine's HWID, making unauthorized access impossible.

Technical Stability (Self-Healing)

Sentralyx has self-healing capabilities with the ThreadWatchdog system:

🔄 24/7 Automatic Monitoring: All critical threads are checked every 30 seconds.
  • Heartbeat Control: Special heartbeat system for scanner thread, "frozen" alarm if no data for 60 seconds.
  • Automatic Restart: If a crashed thread is detected, it's automatically restarted.
  • Maximum Attempts: Each thread has a maximum of 3 restart attempts.
  • State-Safe: Position data and strategy state are preserved during restarts.

Self-Healing Layers:

  1. Pre-Trade Validation: Balance check, risk analysis, maximum position limit.
  2. Real-Time Monitoring: Price spike detection, anomaly detection, P&L tracking.
  3. Emergency Protocols: Global stop mechanism, force close capability.

Yes, file integrity is ensured with Atomic Write I/O guarantee:

⚛️ Atomic Operations: Critical operations either completely succeed or are treated as if they never happened.
  • Transactional File Operations: Write to temporary file, verify, then atomic swap.
  • Crash Recovery: Data consistency is maintained even during power outages or system crashes.
  • ACID Properties: Atomicity, Consistency, Isolation, Durability guarantee.

Example Flow:

  1. Data is written to temporary file (.tmp)
  2. Disk synchronization is performed (fsync)
  3. Atomic replacement with original file (rename)

  • Fast Detection: Connection disconnection is detected within 5 seconds.

  • State Recovery: System state at crash time is preserved and can be restored.

🛡️ 100% Recovery Success: No position loss during connection interruptions.
