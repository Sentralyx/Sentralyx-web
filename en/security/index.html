Controls in the app

Security and risk controls in Sentralyx

API key encryption

Your API keys are encrypted (Fernet) with a key derived from your device's hardware ID and stored on your computer. A settings file copied to another device cannot be decrypted. The app recommends keeping the withdrawal permission disabled on your API key.

Manages only its own orders

Orders sent by Sentralyx are tagged with an ID that starts with "SX". The app manages only the positions and orders it opened itself. If another bot or you have a position on the same account, Sentralyx does not touch it and does not open a new futures position on that symbol.

Exchange-side SL/TP

When a position opens, stop-loss (SL) and take-profit (TP) orders are also sent to the exchange, so they remain there even when the app is closed. If the exchange rejects a new stop order, the stored stop keeps its previous value. During sudden price moves, stop orders may fill with slippage.

Position checks and error handling

The app regularly compares the positions in its records with those on the exchange, closes records for positions already closed on the exchange and tries to restore missing protection. On an unexpected exchange error, the system stops itself.

Risk limits

  • Daily loss limit (in USDT)
  • Maximum number of open positions
  • Maximum position duration: the position is closed automatically when time runs out.
  • Profit protection with trailing stop and break-even

Real mode safeguards

  • A confirmation window appears when switching to real mode; real mode cannot be selected without an API key.
  • No position is opened if the free balance is not enough.
  • The order amount is rounded slightly above the exchange minimum so the stop order is also valid.
  • Trading type and exchange cannot be changed while a real position is open.

These controls aim to reduce risk; they do not remove it. Keeping your account and device secure is also your responsibility.

Your side

User responsibilities

API connection

API key scope

API keys should be created with only the necessary permissions. Withdrawal permission should not be enabled. It is the user's responsibility to verify the permissions on their exchange account.

  • Do not grant withdrawal permission to API keys
  • Disable unnecessary permissions
  • Monitor stop loss and risk limits
  • Do not interpret backtest results as a guarantee of live trading performance

Security settings should be evaluated together with the exchange account, device and user preferences.

Desktop application model

Sentralyx is described as a desktop trading terminal. The user runs the application on their own device and configures exchange connection settings through their own account.

Local execution

According to the product documentation, Sentralyx runs locally on the user's machine. Users are responsible for securing their device, access credentials and files.
